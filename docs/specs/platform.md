## 1. 产品目标

构建面向个人或可信小团队、单机部署的 Web 多智能体工作台。用户创建专家 Agent，绑定 Skills 和 MCP 工具，提交任务，由单个专家或固定总控组织多个专家执行，生成可下载的文件项目，并通过后续对话持续修改项目。

核心闭环：配置能力 → 创建专家 → 提交任务 → 执行与协作 → 检查文件 → 下载交付 → 对话修改 → 保存新版本。

使用体验以对话为中心：用户可直接选择预置或自建专家、Skills 和已连接工具进入任务；不要求每次使用都从创建专家和配置能力开始。配置页面用于创建和维护能力，对话页面用于选择与执行能力。

WorkBuddy 截图仅作为交互参考：可观察到专家“召唤”、Skill“安装”、连接器“连接”、输入框能力标签和示例问题。不能据此认定其内部全部是 Skill、完整内容一次性注入，或存在程序化 Workflow 引擎；本平台按下列需求实现自己的装配行为。

本文件取代 platform-v0.1.md 中的旧规格。platform-review.md 为历史评审依据；发生差异时，以本文件为准。

## 2. 首版范围与技术约束

| 类别 | 首版确定范围 |
| --- | --- |
| 使用方式 | 浏览器访问，本地或可信内网、单机部署；采用一个默认工作空间，首版不实现独立多租户体系 |
| 前端 | React + TypeScript + Vite，与后端分离 |
| 后端 | Python + FastAPI，独立 Python 任务执行进程 |
| Agent 编排 | AgentScope 2.0 系列 Python 版本；平台封装会话能力、预算、确认和项目交付规则 |
| 存储 | SQLite 持久化配置、任务、运行状态与事件，由独立 Python Worker 领取执行；首版不加 Redis。本机磁盘保存 Skill 包、工作文件和版本快照 |
| 模型 | 平台统一维护连接地址、密钥和可用模型列表；创建专家时从列表选择，普通用户不必填写密钥；模型可来自外部服务 |
| 首批模型提供方 | Qwen、DeepSeek、Claude 三家，支持各自官方原生接口；不同协议由适配层处理，不仅支持单一兼容接口 |
| Skills | 平台预置、用户上传，包含说明、参考资料、模板和可执行脚本 |
| 首批业务能力 | 开发、资料整理及办公均纳入首版；Word/Excel/PPT 支持生成、基础读取及平台自产文件的持续修改，外部文件仅承诺基础内容提取 |
| MCP | 远程 MCP；由后端所在机器启动的进程型 MCP；使用 MCP SDK 接入 |
| 多 Agent | 多专家配置；单专家调用预配置协作者；固定总控动态选择已有专家，单层、有限并发 |
| 文件项目 | 通用目录与文件集合；支持完整下载、持续修改和历史版本下载 |
| 运行管理 | 过程展示、取消、超时、有限重试、时长与调用次数预算 |
| 执行边界 | 普通进程执行，不建设沙箱或安全体系；工作目录用于组织文件，不承诺强执行隔离 |

暂不包含：公网不可信用户托管、复杂账号权限、Windows 跨设备连接组件、桌面操作、递归组团、临时生成新专家、任意故障点精确恢复、版本分支合并、技能交易市场、计费、定时自动化、IM 接入、分布式部署、可视化工作流编辑器。

首版不引入 Redis、PostgreSQL 或对象存储，不要求容器平台。Agent 编排采用 AgentScope 2.0 系列 Python 版本和程序化协作规则；保留任务执行过程展示，不提供拖拽式工作流编辑。依赖默认选择满足已选技术约束的稳定版本，在工程初始化时完成最小兼容验证并锁定实际版本；不要求用户另行挑选补丁版本。

服务器托管说明：前述单机指一个后端部署实例，可以部署在服务器，通过浏览器访问。Skills、专家配置和项目文件由平台集中维护；使用预置 Skill 不要求用户下载或上传其代码，页面安装/启用操作将服务端已有能力加入可用列表。自定义 Skill 上传与用户任务资料上传是两个不同入口。服务器托管不自动增加公开注册、多租户或计费范围。

### 2.1 路由与部署约束

- 页面统一基路径 `APP_BASE_PATH`，默认 `/app`；例如 `/app/agents`、`/app/projects`。
- 后端接口统一前缀 `API_PREFIX`，默认 `/api/v1`；各业务模块通过同一个根路由挂载，不各自硬编码完整前缀。
- 健康检查、OpenAPI 与接口文档同样放在该前缀下，例如 `/api/v1/health`、`/api/v1/openapi.json`、`/api/v1/docs`；不另外暴露无前缀的重复入口。
- 任务事件、文件下载、版本下载等业务入口同样使用 API 前缀。
- 前端集中配置 API 地址，不在各页面散落硬编码；路由基路径、静态资源路径和页面刷新回退保持一致。
- 前后端分离不要求不同域名。接口列表、请求结构及代理配置在 Plan 中定义。

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| 专家 Agent | 可复用配置，包含角色、行为要求、模型、Skills、MCP 工具和允许调用的协作专家 |
| Skill | 方法说明与附带资源，不是独立 Agent；需要执行内核提供读文件、写文件、运行脚本等能力 |
| MCP 连接器 | 外部工具服务的连接配置；连接器保存成功不代表服务实际可用 |
| 固定总控 | 自动协作入口的稳定协调角色，负责选成员、拆任务、汇总和检查；不由每次任务动态竞选产生 |
| 默认通用助手 | 未选专家时的默认执行角色，按需使用已启用 Skills 和本轮可用工具；不会自动组建专家团 |
| 子任务 | 有明确输入、输出、依赖和负责专家的执行单元 |
| 项目 | 一条持续会话及其需求、输入资料、多轮运行和文件版本；首次发送自动创建 |
| 运行 | 一轮问答、文件生成或修改的执行实例，具有独立状态、预算和记录；运行内的澄清回复不另开运行 |
| 交付版本 | 文件生成或修改成功并检查通过时保存的完整目录快照；纯问答不创建版本 |
| 能力目录 | 展示预置与自建专家、Skills、连接器的入口，不包含首版范围外的交易市场 |
| 会话能力选择 | 本次对话草稿中选定的专家、Skills 和连接器；选中不等于已经加载或执行 |
| 会话能力覆盖 | 在专家默认绑定之上显式添加或移除的本对话能力；不修改专家模板，不自动传给子专家 |
| 流程说明 | 专家或 Skill 中预写的任务步骤，由执行内核配合模型落实；不等同于可视化或通用工作流引擎 |

## 4. 用户流程与页面

### 4.1 能力配置流程

1. 配置平台模型，确认至少一个模型可调用。
2. 使用预置 Skill 或上传 Skill 包，完成解析和可用性检查。
3. 配置远程或进程型 MCP，测试连接并查看工具列表。
4. 创建专家，指定模型、角色、Skills、MCP 工具和协作者。
5. 选择单专家或自动协作，输入任务、附件和交付要求。
6. 查看执行、必要时回答澄清或取消；完成后查看并下载文件项目。

### 4.1.1 日常使用流程

1. 从首页对话输入框或能力目录开始；可使用预置专家，也可选择已经创建的专家。
   未选择专家也可直接发送，由默认通用助手处理。只有显式选择“自动协作”时，才进入固定总控动态选成员的流程。
2. 专家详情提供职责、版本、依赖与示例问题；“使用此专家”将选择带入对话草稿。
3. Skill 可安装、启用并在对话中显式选择；连接器显示连接状态，缺少配置时提供配置入口。
4. 对话输入框显示所选能力标签。示例问题填入草稿，用户可以修改后发送；点击示例或能力卡片不会自行发起模型调用或外部操作。
5. 发送时确定本轮实际配置，检查本次任务必需依赖；缺失时保留输入和能力选择，说明缺项并提供配置入口，补齐后再执行。未被本次任务使用的连接器异常不阻止执行。
6. 对话中展示过程、实际调用和成果，随后可在项目中继续修改。

点击“新建对话”进入草稿，首次发送自动创建项目。一条持续对话对应一个项目，后续问答和修改均归属于该项目；用户不需要先填写项目表单。项目允许没有文件版本。同一对话延续当前专家/模式及手动能力增减项；切换专家时重新加载新专家默认能力，再应用本对话的手动增减，界面展示最终清单。变更仅影响下一轮。

### 4.2 页面范围

| 页面 | 必备能力 |
| --- | --- |
| 对话首页/能力目录 | 专家、Skills、连接器分类列表，名称搜索、详情、使用入口及示例问题；不依赖公共在线市场 |
| 专家管理 | 列表、创建、编辑、启用/禁用、绑定能力、配置协作者 |
| Skills 管理 | 预置与上传列表、说明与文件查看、导入错误展示 |
| MCP 管理 | 配置、连接测试、工具列表、运行位置与失败信息 |
| 模型设置 | 平台统一配置连接地址、密钥、可用模型列表和默认模型，并测试实际可用性；普通用户只选择模型 |
| 项目工作台 | 对话、输入附件、选择运行模式、预算、状态、专家与工具事件、取消 |
| 文件与版本 | 文件目录、文本查看、单文件与整体下载、历史版本、修改摘要 |

不单独建设专家团市场或可视化工作流编辑器。预置专家详情与使用入口属于首版，不等于建设市场排名、交易或开发者发布体系。

## 5. 功能需求与验收

### F1 专家与能力绑定

- 平台设置集中维护模型服务连接地址、密钥和可用模型列表；创建或编辑专家时从列表选择模型，普通任务对话不要求用户填写密钥。
- 不同专家可以选择列表中的不同模型；默认通用助手和固定总控使用平台配置的相应默认模型。不因专家数量增加而要求独立模型服务。
- 模型连接测试须给出实际成功或具体失败；保存配置不等于已验证可用。尚无可用模型时提示平台配置，不能虚构默认模型可用或报告任务已执行。
- 用户可创建多个专家，填写名称、职责、行为要求和模型，绑定多个 Skills 和 MCP 工具。
- 同一 Skill 或连接器可被多个专家复用；解除绑定不删除共享定义。
- 单专家模式由所选专家担任主专家，只可调用预配置的协作者。
- 每次运行记录所使用的专家、Skill 和工具配置快照；后续配置修改不改变已启动运行的行为定义。连接失效等外部变化仍应明确报错。
- 禁用专家不进入新运行候选范围；历史记录仍可识别其原配置。
- 专家默认绑定是会话能力的起点。用户可在本对话显式添加已启用的 Skills/可用连接器工具，或移除默认能力；这些改动只属于本对话，不回写专家模板。
- 新建其他对话时，从专家默认绑定重新开始，不继承其他对话的增减项。已开始的运行继续使用其配置快照。
- 同一对话中，未调整时沿用当前专家和手动能力选择；切换专家或模式时，保留显式添加/移除项并应用于新默认能力。旧专家仅因默认绑定带入、未被手动添加的能力不自动保留。
- 协作子专家按自己的能力配置执行，不自动继承主对话的全部 Skills 和工具；主专家仍可传递任务所需输入、结果和文件引用。

验收 F1：专家 A 绑定 Skills X、Y，专家 B 绑定 X；从 A 解绑 X 后 B 仍可使用。启动运行后修改配置，新运行生效，旧运行仍可追溯其原配置。

模型配置验收：平台配置并测试模型连接后，该模型可在专家创建列表中选择，普通用户无需再次提供密钥即可发起任务；无模型、连接失败或所选模型不可用时明确提示，不静默改用其他模型。模型密钥不作为专家说明或会话内容的一部分。

会话覆盖验收：专家默认绑定 X，在会话中添加 Y 并移除 X；发送后的有效能力包含 Y、不包含 X，专家模板仍绑定 X。另开对话仍从 X 开始；子专家未绑定 Y 时不会自动获得 Y。上述调整不改变已经开始的运行。

切换验收：专家 A 默认绑定 X、Z，会话手动添加 Y、移除 X；切换到默认绑定 X、W 的专家 B 后，有效能力为 W、Y，X 仍被排除，未手动添加的 Z 不保留。界面展示最终清单，下一轮使用该组合，进行中的旧运行仍使用原快照。

### F2 Skills 导入、加载与执行

- 预置和上传的 Skill 使用相同加载流程；每个包具有 `SKILL.md` 说明，可包含脚本、参考资料和模板。
- 上传后检查包结构和说明是否可解析，显示导入成功或具体缺失项；不能把导入成功等同于脚本可运行。
- 先提供适用场景摘要，执行时按需加载完整说明和相关资源；运行记录区分已绑定与实际加载的 Skill。
- 平台提供文件读写及脚本执行工具，模型能依据 Skill 实际执行步骤并读取结果。
- 脚本使用普通子进程运行，指定任务工作目录，支持超时、输出记录和停止请求；缺少依赖时明确失败。
- 第一批脚本语言、依赖和包格式兼容范围须在 Plan 中列明；不承诺任意脚本环境开箱即用。

验收 F2：上传一个带脚本的 Skill，绑定给专家，运行时实际执行脚本并生成可读取文件；另用缺少入口说明或依赖的包验证错误提示。

### F3 MCP 接入

- 支持填写远程服务连接信息；也支持配置或上传程序，由后端机器启动进程型服务。
- 连接配置包括名称、运行方式和必要连接参数；进程型配置描述启动命令、参数与所需环境。
- 用户可测试连接、查看发现的工具，并为专家绑定选定工具。
- 运行过程显示调用工具、状态与结果摘要；连接失败、进程退出或工具错误必须可辨认。
- 明确显示“远程服务”或“后端机器进程”。浏览器所在电脑不会被默认当作后端机器。
- 连接服务的启动、复用、关闭由平台管理；不要求用户为每轮任务手动重新启动。

验收 F3：远程和进程型 MCP 各完成一次真实工具调用；无效地址与错误启动命令均返回明确失败，不显示可用。上传程序依赖未安装时不得假称启动成功。

### F4 任务执行内核

- 执行流程：解析需求 → 读取配置与适用 Skills → 模型决定动作 → 执行工具 → 将结果送回模型 → 继续或交付。
- 运行实际执行动作，不能仅生成行动计划或口头声称完成。
- 提交任务后返回运行标识，由任务执行进程推进；关闭页面或断开事件流不会取消任务。
- 重要交付信息缺失时提出澄清，保留上下文；普通实现细节由专家决定并记录必要假设。
- 对话输出与可观察执行事件分开呈现，不要求展示模型内部思维链。
- 每个运行有独立工作目录；文件组织并不构成安全沙箱。
- 普通问答可以只交付文本并成功结束，不强制生成文件。生成或修改文件的任务仍必须满足对应文件验收条件。
- 必需依赖检查以本次任务的实际需求为准，不要求所有已安装能力或已配置连接器均可用。可由配置确定的依赖先检查；只有解析需求或规划后才能发现的依赖，在发现后检查，不承诺所有缺项都能在任何模型调用前识别。
- 已知必需依赖缺失时，不启动实质性执行或提前生成部分成果；保留原始需求、附件和能力选择，显示具体缺项及配置入口。补齐后继续使用原请求，不要求用户重输。
- 执行中才发现新的必需依赖缺失或连接失效时，暂停后续派发并进入待用户处理，保留已有记录和产物；已发生的操作不能假称未执行。补齐依赖后继续处理的范围受本轮预算与终态规则约束。
- 不将未读取的数据当成已读取，不擅自改用其他数据源；替代方式只有用户明确改变要求后才适用。

验收 F4：首次发送普通问题后自动创建项目，回答成功但版本列表为空；在同一对话要求生成文件后仍属原项目，并在检查通过后出现首个版本。刷新或关闭页面后重新打开，可找到同一次运行及结果；缺少必要输入时明确等待用户，而不是生成虚构结果。

### F5 多专家协作

- 自动协作模式使用固定总控，从用户创建的专家及已启用的预置专家中选择成员，不创建临时专家。
- 默认通用助手可以调用适用 Skill 和工具，但不因任务复杂而自行切换到自动协作或组建专家团；需要多专家时可以提示用户选择该模式。
- 选定专家调用预配置协作者继续遵循 F1；这种显式选择专家后的既定协作与动态组团不同，不扩大协作者范围。
- 总控给子任务明确目标、必要上下文、输入文件、预期输出与依赖；子专家返回结果摘要及产物位置。
- 独立子任务有限并行，依赖任务等待前置结果；不为了展示多 Agent 而强制拆分简单任务。
- 首版只有主专家/总控与成员两层，成员不再递归分派。
- 子任务在各自产物目录写文件，总控统一汇总到交付目录。同路径冲突需解决并记录，不能静默丢失文件。
- 必需子任务失败或成果缺失时，不标记整体成功；可以保留已完成部分供用户查看。

验收 F5：构造两个独立子任务，其执行时间确实重叠；依赖它们的汇总在结果就绪后执行。用户可以看到负责专家、状态及文件；同名产物不会无提示覆盖。

### F6 过程、取消与失败处理

- 普通分析、读取和项目内文件生成/修改直接执行，不要求逐步审批或每轮先确认完整计划。
- 发送消息、发布内容、删除外部数据等外部变更，在实际执行前展示具体操作、目标和内容/范围，请用户确认一次。主专家、子专家和 MCP 工具执行均遵循同一规则，不因内部转交而绕过确认。
- 确认仅适用于所展示的操作；目标、内容或删除范围改变时重新确认，内容未变的已确认操作不反复询问。可将明确列出的多个操作合并展示确认，但不能用泛泛的计划确认代替具体操作确认。
- 等待确认时进入待用户处理，不执行待确认操作；拒绝则不执行，说明未完成项并由用户决定调整任务或取消，不能把被拒操作报告为成功。
- 执行确认与结果核实分开：确认过的外部写入若结果未知，仍先核实，不因已有确认就盲目重复。执行前展示确认不是引入多租户权限或沙箱体系。
- 展示运行状态、子任务状态、工具调用、错误、文件产出及预算使用量。
- 用户可取消运行；停止新派发，向可取消的模型调用、工具和子进程发出停止请求。
- 对无法取消且已经发出的外部操作标明结果待定或最终结果，不承诺撤销其副作用。
- 网络抖动等瞬时错误有限重试；依赖缺失、配置错误等明确不可自动修复的问题直接报告。
- 重分派只在原候选专家范围内进行，并使用原任务预算；不反复尝试相同的确定性失败。
- 外部写入结果未知时先核实，不能盲目重试而造成重复写入。
- 执行进程重启后，原活动运行标记为中断，保留已记录过程和文件，允许用户重新运行；不承诺从任意代码位置自动续跑。

验收 F6：脚本超时、配置错误、一次瞬时故障、用户取消和执行进程重启分别得到明确状态；有限重试不重置预算，已有产物仍可查看。

执行确认验收：普通分析、读取和项目文件生成不弹逐步确认；模拟发送、发布、删除工具在确认前调用次数为零，确认后仅执行展示的操作，拒绝则不执行。修改收件人、内容或删除对象后旧确认不适用；外部写入结果未知时不自动重复。主/子专家均覆盖该检查。

### F7 预算

- 每轮运行设置总执行时长和模型/工具调用次数两个上限，平台提供默认值与最高限额，用户可在上限内调整。
- 主专家、成员、规划、汇总、重试和重分派共用本轮预算。并行执行按实际经过时间计时，不叠加各成员时长。
- 首次开始执行后计时；初始排队不计入，执行后的工具等待、恢复和内部排队计入。
- 等用户澄清、补齐依赖或确认外部操作时先暂停派发，当前操作结算后暂停执行计时；另设会话等待过期时间，过期后停止本轮。
- 每个实际发出的模型请求和工具执行尝试各计一次，已发出的失败尝试也计数；一次响应触发多个工具时分别计数。
- 配置页连接测试不计入任务预算；执行前被拒绝的请求不算已执行调用。
- 脚本工具调用计一次，脚本内部外部请求不自动等同于平台调用计数；仍由超时和进程管理控制执行。
- 派发前统一检查额度，不能因多个专家并行而超发。额度用尽后不再派发新操作，已发出操作可在剩余时长内完成。
- 若最后的在途操作完成后交付已齐全且无需新调用，可成功结束；否则以预算耗尽结束并保存部分结果。
- 耗尽或取消后不自行重启；下一轮明确提交的修改或重跑使用新预算。
- 费用不作为首版停止条件；调用次数不代表固定金额。

验收 F7：用户超出平台上限的设置被拒绝；并行争用最后一次额度时最多发出一次新调用；重试持续计数；工具长时间无响应也因时长耗尽停止；用户澄清等待不消耗执行时长但可过期。

### F8 通用文件交付

- 用户可向当前对话上传单个/多个文件或项目 ZIP，由服务器保存为当前项目的输入资料；ZIP 中的相对目录结构保留。用户不需要指定服务器系统路径，也不直接修改浏览器电脑上的原文件。
- 上传状态显示处理中、成功或具体错误；ZIP 损坏、格式不支持或超出限制时明确说明。只有成功接收并可读取的附件才作为任务输入，不能假装已读失败附件。
- 后续对话可引用已上传资料，无需反复上传。已有代码项目可从 ZIP 导入后生成修改成果；外部 Office 文件仍按基础提取和重新生成范围处理，不扩大为保真编辑。
- 服务器使用项目工作目录执行，文件生成或修改完成且验收通过后保存可下载的新版本；保留输入副本，不将处理结果写回用户电脑的源文件。用户单纯上传附件不会自行触发执行或创建成功交付版本。
- 用户可以描述所需目录、文件类型和内容；未指定路径时由专家生成清晰结构并展示交付清单。
- 系统依据任务形成必需文件和完成条件，检查实际目录、文件格式与内容要求后交付。
- 首版验收基线包含 Markdown、纯文本、CSV、JSON、文本源代码及 Word/Excel/PPT。办公采用常用现代格式作为交付基线：`.docx`、`.xlsx`、`.pptx`；旧格式、宏文件与嵌入对象的兼容不自动包含在内，具体输入限制在 Plan 列明。
- 三类办公能力均支持生成新文件、基础读取、修改本平台生成且保存在项目版本中的文件；对应报告、数据表和演示文稿。
- 外部上传的办公文件用于基础内容提取和作为参考资料，不承诺原位编辑或复杂排版、宏等特性原样保留。需要基于外部资料制作新文件时，明确这是新生成的交付，不称为保真修改原文件。
- 基础读取覆盖 Word 正文与表格内容、Excel 工作表和单元格内容、PPT 幻灯片文字；不将无法提取的对象或未计算的公式结果编造成已读取信息。遇到不支持的内容时明确说明限制。
- 平台自产文件可在后续对话中调整内容，保存新版本，保留未要求修改的内容。结构变化引起的排版调整可重新生成，不承诺逐字节保留，但原成功版本必须保持不变。
- 办公文件验收同时检查内容和实际格式：Word 标题/段落/表格，Excel 表头/数值及任务涉及的计算，PPT 页数/文字/布局。可解析不等于显示正常；交付前需有对应渲染或打开验证，发现文字溢出、遮挡、损坏等问题不能只凭文件存在报告成功。具体检查工具在 Plan 决定。
- 用户可查看目录、预览文本、下载单文件及保持目录结构的完整包。
- 文件存在不等于有效：CSV、JSON 等执行相应解析检查；代码仅在实际验证后报告可运行；不把改后缀的文本冒充二进制文档。
- 展示验证结果及已知缺项。缺少必需成果时不能报告完整交付。

验收 F8：要求生成指定目录中的 Markdown、CSV、JSON，交付路径正确、文件可解析且内容满足要求；缺失文件与格式错误不能被误判为成功。

输入验收：在当前对话上传文件及含子目录的项目 ZIP，服务器可正确读取并保持相对目录。基于上传资料生成新成果，下载内容符合任务要求，输入副本不被覆盖；损坏 ZIP 返回明确错误。上传 Office 资料不被误当作已支持原位保真编辑。

### F9 持续修改与版本

- 项目内保留对话和交付文件，用户可继续提出修改，无需重新上传已有内容。
- 每轮文件修改默认以最新成功文件版本为基础，复制为本轮工作文件；未涉及文件保留。尚无文件版本时，首次生成从项目输入资料和本轮要求开始。
- 只有实际生成或修改文件且检查通过时，才生成完整版本快照，记录对应运行和增删改摘要；历史版本内容不被覆盖，可独立下载。后续纯问答或无文件变化的运行不生成重复版本，也不改变最新文件版本。
- 修改失败、取消、中断或预算耗尽，不替换上一成功版本；部分结果单独标识。
- 同一项目同一时间只有一个修改运行；重复发起时提示等待或先取消当前运行。
- 首版不实现历史分支、版本合并、任意版本回滚。历史文件不自动到期删除，存储保留与清理能力后续再扩展。

验收 F9：V1 成功后继续对话生成 V2，两版均可下载且 V1 不变；第三轮失败后 V2 仍为最新成功版本。

### F10 对话中的能力发现与装配

- 专家卡片展示名称、介绍和标签；详情展示职责、版本、默认 Skills/工具依赖和可编辑的示例问题。自建专家同样可从目录使用。
- Skill 区分“已安装”“已启用”“本次选中”“本轮实际加载”；连接器分别显示已配置与当前连接可用性，不能混为一个已启用状态。
- 所选专家、Skills 和连接器通过标签或等价清晰组件展示；发送前可以调整选择，输入草稿保持可编辑。
- 角色及流程说明预先定义，执行输入由用户提供；专家不是必须独立训练的模型，也不必拥有独立运行服务。
- 绑定和启用只定义候选能力。执行先提供适用场景摘要，按任务需要读取正文、参考资源和工具；显式选中 Skill 应优先处理并记录实际是否加载，不默认全量注入全部资源。
- 选择卡片不是执行动作；发送任务后才创建运行并执行依赖检查。运行冻结本轮装配配置，后续选择不改写历史运行。
- 未选专家时使用通用助手，按需发现已启用 Skills；用户不必逐个手选，也不应全量加载所有 Skill 正文。明确移除的能力仍按会话覆盖规则排除。
- 界面清楚显示当前使用通用助手、选定专家还是自动协作。默认通用助手不自动升级为动态组团模式。
- 必需连接器未配置、Skill 包缺失或依赖不可用时，指出具体缺项并提供处理入口；不假装该能力已执行。
- 对本次任务必需的缺项，补齐后才进入实质性执行，不提前生成缺少资料的报告或框架；对于未用到的能力，连接异常仅作状态展示，不阻止本轮。
- 普通 Skill 安装不自动创建新的专家。专家模板可组合多个 Skills 与工具，同一 Skill 可复用。
- 预写流程先使用专家/Skill 说明配合现有总控与执行内核；不由“Workflow”一词引入通用 DAG 编辑器。
- 主专家的有效能力由默认绑定加上会话显式添加项、减去会话显式移除项组成；同一能力去重，不能因默认绑定或自动选择而重新引入已移除项。添加与移除冲突以用户最后一次明确选择为准。
- 会话覆盖不修改模板，不自动传播给子专家；专家依赖的能力被移除后若导致任务无法执行，明确提示缺项，不静默补回。
- 手动能力增减项在本对话跨轮保留；切换专家或模式后按新默认能力重新计算有效清单，发送前明确展示。调整只用于下一轮，不改变正在执行的任务，也不回写历史快照或专家模板。
- 保留选择不等于保证服务可用；能力已禁用、包缺失或连接失效时仍显示具体问题。是否阻止执行依据本次任务是否必需，按 F4 的依赖检查规则处理。

验收 F10：从专家卡片和示例问题进入草稿，能编辑后发送；选择一个已安装 Skill 后出现能力标签，发送前不发生工具调用；运行记录可区分所选能力与实际加载/调用；缺失必需依赖明确提示；使用专家无需重新创建配置。能力覆盖与切换按 F1 的场景验收；默认模式按下述场景验收。

默认入口验收：未选专家直接发送任务，通用助手可以实际加载适用的已启用 Skill，但不派发动态专家团子任务；明确切换到自动协作后才允许固定总控选择成员。简单任务即使选自动协作，也不强制拆分。

首批能力覆盖：预置内容必须同时覆盖开发、资料整理和办公，提供可发现的专家/Skill 入口和示例任务，并有真实可执行的能力支撑；不能只提供角色卡片或演示文案。专家数量和技能拆分可在 Plan 中决定；办公按 F8 的生成、基础读取与平台自产文件修改范围验收。

必需依赖验收：要求读取指定外部文档并生成报告，但对应连接器未连接时，保留需求与选择并显示连接入口，不生成无依据的报告或改用其他数据。连接完成后可基于原请求继续执行。另一个未被本任务使用的连接器离线时，不阻止执行。执行中新增必需依赖缺失时，停止新派发并记录等待原因。

## 6. 状态与持久化

运行状态：排队、运行中、恢复中、待用户处理、成功、失败、预算耗尽、已取消、已中断。

- 成功：满足本轮要求；纯问答保存回答而不创建文件版本，文件任务检查必需交付项并在发生文件变更时保存版本。不能将本应生成文件的失败任务降为纯问答成功。
- 失败：无法继续或有限修复失败；保存原因及部分结果。
- 待用户处理：等待补充信息、补齐本次任务必需依赖、确认外部变更或核实结果未知的操作；等待过期转失败并注明原因。等待按 F7 用户等待规则处理，不无休止自动重试或重复消耗调用次数。
- 已中断：执行进程停止，无法保证继续执行；用户可明确发起新运行。
- 终态不因页面重连、服务恢复或迟到结果自动变为运行中。

SQLite 保存模型与能力配置、绑定关系、项目、对话、运行、子任务、预算、事件和版本元数据。文件保存在磁盘，数据库引用其位置。

数据库事务保持简短，不能跨模型或外部工具等待持有写事务；事件按合理批次落盘，不逐 token 频繁写库。任务状态和已保存的成果刷新页面后仍可读取。崩溃时允许丢失尚未落盘的尾部输出，但不得伪造完成状态。

## 7. 首版整体验收场景

### 场景 A：真实能力装配

创建研究专家和文案专家，共用一个 Skill；另给研究专家绑定生成表格的脚本 Skill 和一个 MCP 查询工具。验证两种 Skill 的实际加载、脚本执行和 MCP 调用，不仅验证配置保存。

### 场景 B：并行生成与汇总

输入合成产品资料，要求输出 `docs/brief.md`、`data/channel-plan.csv`、`copy/announcement.md`。总控选取已有专家并行生成独立产物，最终统一产品名称、日期与预算口径。检查执行时间重叠、文件可解析、内容一致并可整体下载。

### 场景 C：失败、取消与预算

分别注入工具暂时失败、脚本依赖缺失、长时间无响应和预算仅剩一次调用。验证有限重试、准确错误、超时停止及并行额度约束；取消后不再派发新任务。

使用可控测试工具验证外部变更确认：确认前未调用，拒绝后不调用，确认后按展示内容执行；普通读取与项目文件生成无需额外确认。不以真实消息发送或真实删除作为默认测试夹具。

### 场景 D：持续修改

基于场景 B 的 V1 要求修改预算，生成 V2；确认涉及预算的文件同步变更，其他文件保留，V1 可独立下载。后续失败尝试不覆盖 V2。

### 场景 E：部署与恢复

调整页面/API 前缀后检查页面刷新、接口、事件及下载均正常。任务执行期间关闭浏览器再打开，运行仍可查看；停止并重启执行进程后，原任务明确标记中断且保留已保存文件。

### 场景 F：办公生成、读取与持续修改

使用同一份合成业务资料，分别生成 Word 报告、Excel 数据表和 PPT 演示文稿，检查内容一致、实际格式有效且能够正常打开或渲染。

随后分别修改报告一个章节、表格一组数据和演示文稿一页内容，验证修改生效、未涉及内容保留、旧版本仍可独立下载。若任务涉及公式，核对实际结果，不能以写入公式文本代替计算验证。

分别上传外部 Word、Excel、PPT 测试文件，验证基础内容可提取并用于生成新成果；包含不支持对象时说明缺失或限制，不承诺保留其原格式。测试不要求支持宏、旧式格式或任意外部复杂文件的原位保真编辑。

## T17 交付正确性补充

- 主运行在执行前提取本轮交付契约：问答或文件任务、必需路径、需要变更的路径、需要删除的路径。使用同一模型和调用/时长预算，记录 `delivery.planned` 事件，界面展示文件目标。无法解析契约时明确失败，不默认为问答。
- 完成时程序核对必需文件存在、要求修改的内容 hash 确实改变、要求删除的路径不存在；不满足时 `delivery_incomplete`，保留部分产物，不发布成功版本。普通问答可以不创建文件版本。
- 契约由模型理解自然语言，属于执行约束，不能保证需求提取或任意内容语义完全正确；日期、数字、业务规则及无依据事实仍需业务验收。
- 子任务文件差异包含新增、修改、删除；依赖继承完整变更，后续依赖任务可以覆盖祖先的修改，独立分支的修改/删除冲突必须显式解决。删除最后一个文件仍保存空版本，历史版本不变。
- 上下文预检按保守 token 估算而不是 UTF-8 字节数计量；实际供应商 tokenizer 为准。保留输出额度与余量，超限明确失败。
- Office 渲染同时检查几何排序和原 PDF 顺序，避免字体回退和跨行表格造成错误缺失判定。中文正文/标题统一字体。Excel 默认图表排除末尾合计行；可用 chart_range 明确覆盖数据行范围。
- 生成内容必须区分已给定事实与假设/建议，不能把尚未实现的程序行为写成已实现功能。对确定格式、路径和数值的自动断言之外，再进行人工审阅；首次失败和重测均保留。

## T22 上下文与协作架构（2026-11-11）

本节落实 [架构需求清单](../agent-architecture-backlog.md) CTX-01–07、AGENT-01–04。任务计划见 [T22](../plans/T22-architecture.md)，证据及未覆盖项见 [Test / Check](../validation/T22.md)。

- **CTX-01/02**：每次主/子 Agent 模型决策前预算完整编码请求（system、消息、工具schema）；触发比例默认80%，目标60%，再扣除配置输出额度及2048 token余量。token采用保守估算，真实值以供应商usage为准。只在完整工具调用/结果边界压缩，当前用户要求保留原文。项目历史摘要及运行内摘要持久化，附版本、覆盖范围、来源hash和原始资料。摘要模型调用同样占用预算；空摘要、过大输入或仍超限明确失败。摘要语义仍需验收，不能保证模型绝不漏事实。
- **CTX-03**：工具大结果统一存盘，默认超过12000字节返回512字节预览、SHA256引用及完整性标记。单结果64MiB、每轮所有Agent合计256MiB；超过上限明确失败，不把截断称完整。读取默认8192字节，最多16384。成功/失败运行默认30天后可清理；运行中、排队及interrupted运行保留引用。备份包含数据库、runtime结果和agent_budgets。
- **CTX-04**：每次模型调用前保存AgentState、消息、摘要版本、已加载能力、协作状态、文件基线和预算；工具开始前将checkpoint标记不安全。仅允许interrupted运行在安全边界恢复同一run；验证冻结配置、文件hash、引用及后续轮次。耗尽预算不重置。外部工具结果未知不自动重放；用户先核对再新提交。待确认交互仍由原交互表留存，不能自动将未知结果当批准执行。没有任意指令点/运行中子任务单独续行承诺。
- **CTX-05**：system及已有摘要消息保持稳定，新摘要追加到独立消息；超过目标时记录基线轮换。缓存前缀边界与执行checkpoint分别管理，不能无限冻结每个执行checkpoint之前的全部内容。仅保证应用请求编码的前缀策略，不保存远程KV cache，也不预先承诺缓存命中或费用下降。
- **CTX-06**：记录上下文估算、压缩前后大小、摘要版本/基线轮换、结果落盘/读取、checkpoint和预算事件；model.usage记录供应商输入/输出及可用缓存token数，未知为null。界面执行记录可查看这些指标。跨供应商/不同负载指标不合并得出收益结论。
