# T11–T15 实施记录

日期：2026-11-10。实现完成，最终验收证据见各任务 validation 文档。

## 模块与契约

- `runtime/collaboration.py`：固定总控仅可从提交时冻结的候选中分派。每批 1–12 项有向无环任务，最多 3 个同时执行。子专家独立 AgentScope Agent、模型配置、Skills、MCP、历史上下文和工作目录；无递归分派工具。依赖成功后才启动，依赖产物复制到下游。
- 合并只接受成功子任务文件。不同子任务对同一路径给出不同内容时保留冲突；总控读取候选并调用 resolve_conflict 明确选择。未解决冲突/未修复失败不得发布成功版本。重分派通过 replaces 指向失败子任务 UUID；外部操作结果未知的失败禁止自动替代。
- SQLite 新增 `run_lanes` 和 `subtasks`，迁移 `0004_collaboration`。只有所有活动通道停止工作才暂停计时。等待任务保留协程和持久化交互，但释放全局两个活动运行名额；恢复先重新取得名额。取消/进程中断更新子任务状态。
- `runtime/office_models.py`：Pydantic 校验 Word、Excel、PPT 的结构化输入，错误表格维度在写文件之前拒绝。
- `runtime/office.py`：python-docx/openpyxl/python-pptx 生成和读取；自产文件携带 `.agentbuddy.json` 内容模型。修改提交完整更新后的模型并重新生成，先核对文件哈希。这里采用完整模型替换，不额外实现 JSON Patch API。外部文件仅提取内容，不能直接作为自产文件编辑。
- LibreOffice 实际导出 PDF；Excel 先另存重算，检查公式缓存、错误值及可选 expected；PyMuPDF 输出 PNG、检查页面边界和正文覆盖。PPT 长正文自动分页，柱状图单独分页；形状必须在画布内。PDF 按坐标顺序提取文字，避免中文标题字体分段导致错误漏字判断。
- 发布前统一校验 Office 文件，匹配文件哈希的报告才允许发布；旧版本按既有不可变规则保留。预览、逐页 PNG、报告随 ZIP 交付。验证范围是格式、公式和渲染，不是业务结论正确性或任意复杂排版保证。
- 预置 5 个 Skills：项目文件整理、开发与验证、Word、Excel、PowerPoint；5 个专家：开发、资料整理、文档、表格、演示。通用助手为系统默认角色，总控为固定运行角色。预置只在首次缺失时创建，不覆盖用户修改和启用状态。
- 开发 Skill 可以实际执行项目内 Python 测试脚本并保留退出码/日志；其他语言生成源码不等于完成运行验证。

## 前后端接口

均由 API_PREFIX 统一挂载，默认 `/api/v1`：

| 接口 | 用途 |
| --- | --- |
| POST /runs | selection.mode 为 general/expert/team；原有选择及预算字段保持兼容 |
| GET /runs/{id}/tasks | 子任务计划、依赖、状态、时间及结果 |
| GET /office/dependencies | 渲染器是否可定位与预期字体 |
| GET /files/{id}/content?path=... | 校验清单/哈希后返回单文件；文本、PDF、PNG 可预览 |

页面提供执行模式、目录一键使用、示例填入草稿、子任务状态和文件预览链接。切换模式/专家保留手动增减项，影响下一轮。没有模型时给设置入口；缺渲染器时给依赖提示，普通文本任务仍可执行。
