日期：2026-11-10。环境：Windows，现有授权 DeepSeek，隔离目录 `data/validation/t17-uat`。

## 结论

15 类任务均取得通过检查的最终产物；其中部分经历失败、代码/配置修正后重测，部分在人工审阅后由 Agent 继续修改。不是一次性 15/15 成功，不等于任意任务都能无人审核交付。

验收脚本只准备输入、提交任务、运行平台 Worker、读取/执行产物并检查；业务交付文件由平台 Agent 实际生成。没有以验收脚本补写缺失产物。

## 正确性修复

1. 执行前冻结交付契约，执行后核对文件存在、变更及删除；缺文件或仅口头完成不能发布成功版本，普通问答仍可成功且不建版本。增加正文伪完成的集成回归。
2. 协作合并记录删除并传递依赖；祖先/后继修改按依赖顺序，独立修改与删除冲突需显式解决；删除全部文件仍保存空版本。
3. 上下文预检原先把 UTF-8 字节当 token，过早失败；现用有余量的估算。供应商 tokenizer 仍是最终依据。
4. Word 表格跨行与字体回退可能使 PDF 两种提取顺序各自不完整，现同时核对原顺序和几何排序，不删除正文覆盖检查。正文和标题明确统一中文字体，实看修复后风险标题无重叠。
5. Excel 图表原先默认把末尾合计作为类别，已排除合计/总计/total，可显式指定 chart_range。实看最终图仅有开发/测试/设计，公式合计仍为20000。
6. 修正首页过期阶段文案；正式产物优先，预览/元数据折叠展示；页面可见本轮交付清单，文件变更统计排除辅助文件。

## 实测发现与审阅

- 代码补测试、PPT、协作最初遇到上下文限制；活动页曾输出截断；Word 曾收到无效工具 JSON。失败没有被包装成成功，记录保留。
- 最终验收配置：context_window=131072，max_output_tokens=8192；每个任务最多120次调用、420秒。只改隔离验收配置，用户默认工作空间未改。此前32K/4K的协议测试配置不适合较长业务任务，交付部署应按实际模型配置。规格参考 [DeepSeek 官方说明](https://api-docs.deepseek.com/quick_start/pricing/)，这里使用的是验收额度，不是宣称模型最大能力。
- PPT首次内容断言未识别20,000千位分隔格式；检查实际内容正确后修正断言，保留原失败，复查同一产物通过，未要求 Agent 改成测试专用格式。
- 多专家策划曾遗漏发布文案中的日期/总预算，运行状态成功不代表语义完整。加入最终文件一致性要求后原任务重测通过。
- 人工审阅发现需求文档无依据背景、配置说明宣称不存在的程序能力、活动页面虚构楼层/期数/免费等信息。由 Agent 在原项目上修改，明确事实与假设/待确认；旧版 ZIP 不变。
- 本地 MCP echo 是真实协议调用的可控测试服务，不代表外部业务服务供应商已验收。

## 体验验收

- 可接受：文件闭环、真实协作、持续修改、版本保留、Office基础排版及下载可用。Python工具另起进程校验负数退款和错误退出，生成的unittest实际执行。
- 已人工查看：Word最终整页、Excel最终数据/图表、PPT预算页；中文清晰，所看页面无明显越界。HTML检查了源码、响应式规则和内容，未声称跨浏览器/手机视觉验收。
- 待优化：会话标题直接截取长需求，列表拥挤；能力配置占据较多纵向空间；助手Markdown仍以原始文本展示；错误缺少针对性的修复引导。
- 验收意见：适合可信用户小范围试用。业务语义仍需审核，不能宣称无人值守的商业交付质量；多次真实执行出现无效工具JSON及内容遗漏，已如实保留。
